# Module 4, Lab 1: Text-to-Speech Assistant for IT Infrastructure

## Lab overview

This standalone lab shows how IT operations teams can turn infrastructure messages into spoken audio. The main deliverable is the Jupyter Notebook `module4_lab1_text_to_speech.ipynb`. It sends sample IT messages to the OpenAI Text-to-Speech (TTS) API, saves the results as MP3 files, plays them inside the notebook and records every file in a simple log.

The notebook is written for mixed audiences. Participants with Python experience can read and extend the code. Participants without Python experience can run the cells in order and change a few marked variables.

## Learning outcomes

By completing the lab, participants can:

1. Convert IT infrastructure text into speech.
2. Integrate an OpenAI TTS model using Python.
3. Select different voices for different operational scenarios.
4. Generate critical incident notifications.
5. Generate infrastructure status announcements.
6. Create accessibility-friendly audio.
7. Convert analysis outputs into audio.
8. Play and manage generated audio files.
9. Maintain a simple audio generation log.
10. Compare different voice outputs.

## Business scenarios

| Scenario | Sample message in the notebook | What the audio is for |
|---|---|---|
| Critical database alert | `critical_alert` | Reaching on-call staff who are away from a screen |
| Server status update | `server_status` | Spoken status summaries at handover meetings |
| Scheduled maintenance notice | `maintenance_notice` | Announcing planned outage windows to users |
| Security update | `security_update` | Briefing teams on investigations that need attention |

The notebook also converts analysis text from earlier IT infrastructure labs (for example, server rack analysis or monitoring summaries) into audio. The integration is loosely coupled: the sample analysis text is included in the notebook, so no other lab output is needed.

## Prerequisites

- Python 3.9 or newer.
- Jupyter Notebook or JupyterLab (installed through the requirements file).
- An OpenAI API key with access to the Text-to-Speech API.
- An internet connection. Audio is generated by the OpenAI service.
- No prior Python experience is required to run the notebook.

## Audio generation workflow

1. Choose or write an operational message (a sample in `sample_texts`, or your own text).
2. Choose a voice from `VOICE_OPTIONS` and a speed between 0.25 and 4.0 (1.0 is normal).
3. `convert_text_to_speech` sends the text, voice, speed and model (`tts-1` by default) to the OpenAI API.
4. The returned audio is saved to `audio_output/` with a name such as `tts_alloy_20261117_134456.mp3`. If that name already exists, a number is added, so no file is overwritten.
5. The generation is recorded as one row in `tts_logs/audio_generation_log.csv`.
6. The audio player is shown in the notebook when `PLAY_AUDIO` is `True`.

## API configuration

The notebook reads the key from the environment variable `OPENAI_API_KEY`. Choose one of these options.

**Option A: environment variable (recommended for a single session)**

- Windows PowerShell: `$env:OPENAI_API_KEY = "your-key-here"`
- macOS or Linux: `export OPENAI_API_KEY="your-key-here"`

Start Jupyter from the same terminal after setting the variable.

**Option B: local `.env` file**

Create a file named `.env` in the lab folder with one line:

```
OPENAI_API_KEY=your-key-here
```

Do not share this file, and do not commit it to source control. The lab package does not contain a `.env` file or any API key.

**Security notes**

- The notebook never prints the API key.
- The notebook never places the key inside a cell. Keep it in the environment or the `.env` file.
- If the key is rejected, the notebook stops with a clear message instead of creating placeholder audio.

## Troubleshooting

| Symptom | Likely cause and fix |
|---|---|
| `OPENAI_API_KEY is not configured` | The key is not set in this session. Set it (see API configuration), restart Jupyter from that terminal and run from Cell 3. |
| `The OpenAI API key was rejected (error 401)` | The key is wrong, expired or revoked. Create or copy a valid key. |
| `Audio generation failed ... Details: ...` | Usually a connection problem or an unavailable model. Check the internet connection, then read the details shown. |
| `Invalid voice` | Use one of the voices listed in Cell 9: alloy, echo, fable, onyx, nova, shimmer. |
| `Unsupported speed` | Use a number from 0.25 to 4.0. |
| `NameError: name '...' is not defined` | A cell was run out of order. Restart the kernel (Kernel > Restart) and run all cells from Cell 3. |
| No sound in the notebook | Check the computer volume, and check that `PLAY_AUDIO` is `True`. The MP3 file is still saved in `audio_output/`. |
| `ModuleNotFoundError` | Install the requirements again: `pip install -r lab1_m4_requirements.txt`. |
| Log file looks empty | Run at least one example. The log is created the first time audio is generated. |
